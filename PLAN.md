# jman-api Development Plan

This document outlines the plan for creating a REST API (`jman-api`) that serves the cached data generated by the `jman` CLI.

## 1. Project Structure & Build Setup

- [x] Create a new entrypoint directory: `cmd/jman-api/main.go`.
- [x] Update `Makefile` to include a `build-api` target and modify the default `build` target to compile both `bin/jman` and `bin/jman-api`.
- [x] Update GitHub Actions workflows (`.github/workflows/build.yml`) to ensure both binaries are built and released.

## 2. Shared Cache Logic Refactoring (Read-Only API)

- [x] Review `internal/cache` methods to ensure they return pure Go structs (from `internal/models/`) and handle missing cache files gracefully.
- [x] Ensure the API operates in a **read-only** mode. The `jman` CLI is responsible for creating/updating the cache (e.g., pulling from SpinupWP/WPVuln), while `jman-api` only reads the generated JSON files from the cache directory.

## 3. API Design & Routing

Since the project uses Go 1.25+, we will use the standard library `net/http` enhanced routing capabilities.

**Proposed Endpoints:**

- [x] `GET /health` - Basic health check to confirm the API is running.
- [x] `GET /api/plugins` - Return the cached plugins data (`internal/cache/plugins.go`).
- [x] `GET /api/servers` - Return the cached server and site data (`internal/cache/spinupwp.go`).
- [x] `GET /api/vulns` - Return cached vulnerability data (if currently cached locally).

## 4. Configuration

- [x] Add configuration support for the API (e.g., listening port). Default to `8080`.
- [x] Allow configuration via environment variables (e.g., `JMAN_API_PORT=8080`).
- [x] Ensure the API correctly resolves the XDG cache directory via `internal/config` to locate the files generated by the CLI.

## 5. Middleware & Polish

- [x] Add basic logging middleware to track incoming requests (Method, Path, Duration).
- [x] Add CORS headers if the API is intended to be consumed by web frontends.
- [x] Add basic error handling to return proper HTTP status codes and JSON error messages (e.g., `500 Internal Server Error`, `404 Not Found` if cache is missing).

## 6. Documentation

- [x] Update `README.md` with instructions on how to start `jman-api`.
- [x] Document the available API endpoints.
